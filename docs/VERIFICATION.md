# 计算引擎验证体系

语言 / Language: **简体中文** | [English](VERIFICATION_EN.md)

本工具的定量计算不是"感觉对"，而是用三层可复现的验证方法背书。所有验证可一键复跑：

```bash
node tests/verify-calc.js
```

## 第一层：已发表公开算例对照

| 算例 | 结构 | 期望结果（已发表） | 工具结果 |
|---|---|---|---|
| 双泵冗余系统（NUREG-0492 风格） | AND(0.01, 0.01) | 1.0E-4 | 1.000000E-4 ✓ |
| 生产线计划外停机（CSSBB 教程） | OR(AND(0.02,0.05), OR(0.01,0.004)) | 0.014946 | 1.494604E-2 ✓ |
| 控制器+双执行器（教学算例） | OR(0.02, AND(0.10, 0.05)) | 0.0249 | 2.490000E-2 ✓ |
| 经典 2oo3 表决（p=0.1） | 表决门 2/3 | 0.028 | 2.800000E-2 ✓ |

另验证失效率换算：λ=1e-5/h、t=10000h → q=1−e^(−0.1)=0.095163，精确吻合。

## 第二层：随机树 Fuzz 测试（布尔枚举精确解对照）

随机生成 300 棵故障树（OR/AND/表决门混合，**半数刻意含共用底事件**），每棵树同时用两种方法计算：

- **工具引擎**：无共用事件走独立性递归公式；检测到共用事件自动切换 ROBDD
- **精确解**：遍历所有底事件状态组合（2ⁿ 枚举）的布尔真值统计——数学上无假设、绝对正确

**结果：300 棵全部通过，最大绝对误差 1.2×10⁻¹⁵（浮点精度级别）。**

> 这层测试的历史价值：早期版本曾在"共用底事件"场景系统性出错（独立性递归把同一事件的多次出现当独立事件处理），正是被蒙特卡洛验证的 15σ 偏差暴露、随后引入 BDD 修复的。

## 第三层：Aralia 公开基准题蒙特卡洛交叉验证

[Aralia 故障树基准库](https://github.com/rakhimov/scram/tree/develop/input/Aralia)（经 SCRAM 项目分发）是故障树领域公认的验证基准。用 `scripts/openpsa-convert.js` 将 Open-PSA 格式转换为项目文件后计算：

| 基准题 | 规模 | 顶事件精确概率（本工具） | 蒙特卡洛验证 |
|---|---|---|---|
| chinese | 61 节点 / 25 底事件 | 1.76×10⁻⁹ | 概率×500 缩放后与 MC 统计一致 ✓ |
| das9202 | 122 节点 / 49 底事件 | 1.02×10⁻²⁵ | 同上 ✓ |
| isp9606 | 130 节点 / 89 底事件 | 4.08×10⁻⁹ | 同上 ✓ |

> 说明：原始概率下顶事件概率为 10⁻⁹ 量级，蒙特卡洛（≤10⁶ 抽样）无统计验证力，故将底事件概率按比例放大后验证**结构与门逻辑的正确性**；概率数学本身由第二层枚举精确解证明。`examples/` 中的三个基准题文件为原始概率版本，可在工具中直接打开复核。

## 复现基准题验证

```bash
# 1. 下载基准题（Open-PSA 格式 XML）
curl -sL "https://raw.githubusercontent.com/rakhimov/scram/develop/input/Aralia/chinese.xml" -o benchmarks/chinese.xml

# 2. 转换为项目文件（可选：概率缩放倍数用于 MC 验证）
node scripts/openpsa-convert.js benchmarks/chinese.xml out.fta.json
```

## 边界与已知限制

- 支持的门类型：OR / AND / 表决 k/n（连贯静态树）。INHIBIT / PAND / XOR / NOT 等非连贯或动态门在路线图中
- 概率输入假定各底事件相互独立（共因失效 CCF 未显式建模，可用共用底事件近似表达）
- 房形事件为确定性事件（q=0 或 1），参与 OR/AND/表决运算
